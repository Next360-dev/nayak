# Module specs: all 36 modules, executable. Written 2026-11-24. Read `MASTER_PLAN.md` first.

Common to every module (not repeated below): typed Pydantic models; office scope on every query; audit event on every state change; metrics event where listed; paginated lists with "Mine / All / Overdue" filters; web + phone screens from the module page template; strings in `frontend/src/i18n/strings.js` (synced to the phone by `scripts/sync_i18n.mjs`), English + Telugu; works with AI off.
Legend: Task = ID in MASTER_PLAN. St: D done / P partial / N new. "Done when" = acceptance.

## Pillar 1: Political Intelligence
**2 Competitor / watchlist alerts** | St P | Task P1 | Data: `watchlist(office, name, aliases)` max 5, `watch_hits(entry, url, platform, detected_at, notified_at, acknowledged_at, false_positive)` | API: `GET/POST /api/watchlist`, `POST /api/watchlist/check-now`, `POST /api/watch-hits/{id}/ack` | Screens: Intelligence > Watchlist, hit list with Acknowledge / False positive | Rules: only public sources within platform terms; alerts send-once; aliases come from the gazetteer (E1) | Job: `watchlist_check` every 30 min | Metrics: detected->notified->acknowledged times | Done when: a new hit alerts staff once, acknowledgement is recorded, latency shows on the metrics page.
**26 News intelligence** | St D | Task P2 | Harden: per-source adapters, `source_health` table, stale-source alert to admin, tone v2 (E2), priority (E3), dedupe (E4) | Done when: stale source turns the Jobs page red; accuracy report in CI.
**27 Social media intelligence** | St D | Task P2 | Harden: tone v2, trend view separate from real-time alerts (weekly counts by platform/tone/topic), neutral class kept | Done when: trend page and alert feed are separate; crawl limits tested.

## Pillar 2: Legislative Intelligence
**3 Legislative inbox** | St N | Tasks L0, L1, L2 | L0 (report only): list official sources, format, stability, licence, sample parse. Then Data: `legislative_items(type: question|answer|speech|debate|mention|government_response, member, house, date, topic, source_url, verified, verified_by)` | API: list/filter by type, member, date; `POST /api/legislative/{id}/verify` | Screens: Intelligence > Legislative with one tab per record TYPE (never one blended score), source link on every row, "unverified" label | Rules: types stay separate; every record has its official source; human verifies before it counts | Job: `legislative_fetch` daily; OCR (E8) for scanned PDFs | Done when: 100 real records parsed, each with a working source link, verification queue works.

## Pillar 3: Constituency Management
**5 Grievances** | N | C1 | Data: `grievances(ref_no, category, location, village, description, evidence_files, status: new|assigned|in_progress|resolved|closed, assignee, due_at, sla_hours)`, `grievance_events` | API: `POST /api/public/grievances` (rate limited, honeypot), `GET /api/public/grievances/{ref}` status check, staff CRUD, assign, escalate, resolve with verification note | Screens: Constituency > Grievances list (Overdue first), detail with timeline, public form + status page | Rules: unique reference number; SLA clock; auto-escalate when overdue; resolution needs a verification note | Jobs: `overdue_reminders`, `grievance_escalation` | Metrics: created/assigned/closed times, overdue % | Python engine: category suggestion by classifier (E-style TF-IDF), fallback "unsorted" | Done when: full lifecycle test, citizen sees status by reference.
**6 Projects** | D | C2 | Harden: typed input, tests, add `evidence_files`, states `proposed|approved|sanctioned|in_progress|completed`; completed requires evidence (spec rule), delay flag from milestone dates | Done when: cannot mark completed without evidence.
**11 Field staff app** | N | C6 | Data: `field_assignments`, `field_checkins(lat, lng, at)`, `field_reports(text, audio, photos)` | API: assignments, check-in, submit report (idempotent by client id) | Screens: phone Field mode: today's assignments, check in, camera, voice note (stored; transcription optional later), works offline with a queue that syncs | Rules: conflicts resolved by client timestamp + server audit; geotag kept with photo | Done when: airplane-mode test: create 3 reports offline, sync once online, no duplicates.
**12 Schemes info** | N | C5 | Data: `schemes(name_en, name_te, eligibility, documents, steps, deadline, official_url, updated_at)` | Screens: searchable list, detail, "guidance only" banner | Rules: content entered by staff, each scheme shows source URL and last verified date | Done when: 20 sample schemes searchable in both languages.
**14 Map & heatmap** | N | C7 | Data: lat/lng columns on grievances and projects; boundaries file per constituency (owner supplies) | API: `GET /api/map?layer=grievances|projects&category=` | Screens: map with clusters and heat layer, filter by category/status | Rules: show only items with reliable coordinates; unknown location stays off the map | Done when: grievances and projects plot correctly for one real constituency.
**17 Feedback & surveys** | D | C8 | Harden + analytics: counts by category, village, week; keep per-leader link; trusted-proxy IP for rate limits (`TRUST_PROXY=1`) | Done when: results page shows trends; isolation test passes.
**18 Funds tracker** | N | C4 | Data: `fund_allocations`, `fund_proposals`, `fund_sanctions`, `fund_releases`, `fund_expenses` (separate tables = separate stages) | Rules: amounts are integers in paise, stage order enforced, never edited (corrections are new rows), every row audited | Screens: per-year summary, stage pipeline, utilisation % | Done when: cannot release more than sanctioned; audit shows every change.
**19 Emergency alert** | N | C3 | Data: `incidents(type, location, status: unverified|verified|resolved, coordinator)`, `incident_actions` | API: register, verify, assign, update, close | Rules: unverified is labelled; push fan-out to the emergency group via the notification bus; ack required | Done when: incident push reaches the group and acknowledgements are tracked.
**32 Emergency directory** | N | C3 | Data: `emergency_contacts(category: police|fire|hospital|utility|disaster, jurisdiction, phone, escalation_order, verified_at)` | Screens: one-tap call list by category and area | Rules: shows last verified date; unverified contacts are marked | Done when: escalation path shown in order.

## Pillar 4: Office Administration
**O1 Record engine (foundation for the rest)** | Task O1 | Generalise `work_items` into `records(kind, owner, assignee, status, due_at, ref_no, payload jsonb)` + `record_events` + `record_files`; each module registers its kind, statuses, allowed transitions and payload schema (Pydantic). Letters keep working (migration moves rows). Done when: letters pass all old tests on the engine; adding a new kind needs only config + schema.
**7 Visitors** | N | O2 | Kind `visit`: name, phone, purpose, meeting_with, appointment link, queue_no, status `waiting|met|referred|followed_up`, notes, referral | Screens: Office > Visitors: today's queue, check-in form (3 fields), mark met, referral, follow-up task | Rules: phone numbers masked in lists, full number on detail with access log | Done when: queue order and follow-up task creation tested.
**10 Appointments & tours** | N | O3 | Kind `appointment` (who, purpose, place, start/end, status) and `tour` (route, stops, dates) | Screens: day/week list (not a heavy calendar first), conflict warning, reminder push | Job: `appointment_reminders` | Rules: time zone Asia/Kolkata, no double booking without override | Done when: conflict test and reminder test with fake clock.
**29 Shift handover** | N | O4 | Kind `handover`: auto-collects open items, overdue tasks, pending approvals, alerts; staff add notes and risks; next shift acknowledges | Rules: cannot end shift without acknowledging the previous one (soft warning) | Done when: handover snapshot matches live counts.
**30 Delegation** | N | O5 (Claude builds) | Data: `delegations(from_user, to_user, scope(module + office), starts_at, expires_at, revoked_at)` | Rules: delegate acts "on behalf of", every action logs both people; expires automatically (job `expire_delegations`); cannot delegate more than you hold | Done when: permission matrix tests incl. expiry and revoke.
**28 Unified approval inbox** | P | O6 | `GET /api/approvals` returns letters, composed posts, suggestions, delegations awaiting the leader in one shape (kind, title, from, age, risk flag) with approve / reject / change request | Rules: nothing AI-made or public goes out without an approval record | Done when: one list, one-tap decisions, audit complete.
**4 Activity reports** | N | O7 | Data: `activities(date, place, category, description, status: announced|in_progress|completed, evidence_files)` | Screens: quick add (phone, photo), report builder (month/quarter/year/custom) to PDF | Rules: "completed" needs evidence; a social post alone is not evidence | Python: Jinja2 + WeasyPrint with Telugu fonts | Done when: yearly PDF generated from sample data with photos.
**31 Meeting brief** | N | O8 | Composes appointment/meeting + attendees + previous decisions + open actions + related letters | Rules: reads from other modules only; no new data | Done when: brief renders for a sample meeting in under 2 s.
**9 Department tracker** | N | O9 | Kind `dept_request`: department, officer (from directory), reference, deadline, status, outcome | Job: reminders + escalation history | Metrics: % with owner, deadline, outcome | Done when: overdue request escalates.
**15 Meetings & minutes** | N | O10 | Data: `meetings`, `agenda_items`, `attendees`, `minutes`, `action_items` (become tasks) | Done when: action item creates a task with owner and due date.
**16 Events** | N | O11 | Data: `events`, `venues`, `guests`, `checklists`, `attendance`, post-event report | Done when: checklist completion and attendance report work.
**20 Records & files** | N | O12 | Data: `files(owner, category, versions, permissions, ocr_text)` on a storage interface (local disk first, S3-compatible later) | Rules: versioned, permission per record, access log, virus/size/type checks | Job: `ocr_queue` | Done when: upload, version, OCR text searchable, permission denied tested.
**13 Contact directory** | P | O13 | Data: `contacts(name, role, department, jurisdiction, phone, email, verified_at)` + CSV import with dry run (exists) | Rules: phone/email "Not available" until real data; `verified_at` visible | Done when: real data for the pilot office loaded.
**34 Tasks v2** | D | O14 | Add priority, dependencies, completion evidence, comments, overdue reminders | Done when: dependency blocks start; reminders fire once.

## Pillar 5: Assistance (plain Python first)
**21 Assistant** | P | A1 | `POST /api/assistant/ask {text}` returns {answer, sources[]}; about 20 intents by rules + fuzzy matching (rapidfuzz) over the user's own data: urgent stories, approvals, today's schedule, overdue tasks, visitor queue, grievance counts; Telugu + English keywords | Phone: typed box + device speech in and out; web: panel | Rules: reads only what the user may see; sensitive actions need confirmation | Done when: 20 intents tested in both languages; works offline of any AI.
**22 Drafting** | N | A3 | Templates (letter, invitation, follow-up, petition reply) with placeholders and letterhead; fill from a record; PDF | Rules: human reviews before sending | Done when: 5 templates render Telugu and English correctly.

**24 Daily briefing** | P | A2 | Template over real numbers and top sentences: alerts, approvals, schedule, overdue, grievances | Job: `briefing_email` daily | Done when: briefing equals live data and links to each item.
**25 Knowledge search** | N | A5 / B0.12 | `GET /api/search?q=` across news, letters, grievances, projects, tasks, files, contacts; permission-aware; grouped by module | Done when: result never includes something the user cannot open (tested per role).
